Desenvolvimento de Software¶

Este é um livro aberto sobre como construir, entregar e manter software. Em oito capítulos, ele reúne fundamentos clássicos da engenharia de software, consolidados por autores como Sommerville e Pressman, e as práticas atuais: métodos ágeis, arquitetura, testes automatizados e integração e entrega contínuas (CI/CD).

🧭 Antes de começar¶

O livro pressupõe lógica de programação e experiência com pelo menos uma linguagem. Conhecer orientação a objetos ajuda no Capítulo 4, que traz uma revisão curta. Os exemplos usam Python (pytest, FastAPI) e GitHub Actions.

Os capítulos seguem uma ordem progressiva, mas também podem ser consultados separadamente.

🎯 Estrutura do Livro¶

📘 Parte I: Fundamentos (Capítulos 1-2)¶

O que diferencia software de outros produtos, por que a engenharia de software nasceu como disciplina, a ética e as licenças, e como as equipes organizam o trabalho: cascata, desenvolvimento incremental, Manifesto Ágil, Scrum, Kanban, XP, estimativa e riscos e a cultura DevOps.

📙 Parte II: Requisitos e projeto (Capítulos 3-4)¶

Como descobrir, prototipar e registrar o que o sistema precisa fazer, cuidar da usabilidade e da acessibilidade, modelar seus conceitos, comportamento, estrutura e dados, aplicar princípios e padrões de projeto e tomar decisões de arquitetura, inclusive as de segurança.

📗 Parte III: Construção (Capítulos 5-6)¶

Código legível e seguro, tratamento de erros, concorrência, depuração, revisão, controle de versão, verificação e validação, e testes, dos unitários aos de aceitação, com projeto de casos de teste e TDD.

📕 Parte IV: Entrega e evolução (Capítulos 7-8)¶

Pipelines de integração e entrega contínuas, contêineres, testes de segurança, versionamento, implantação com HTTPS e a vida do software em produção: manutenção, dependências, resposta a incidentes, débito técnico, sistemas legados, cópias de segurança e observabilidade.

🧰 Apêndices¶

O vocabulário de HTTP e APIs e os comandos de Git e contêineres usados ao longo do livro.

🧪 O projeto condutor: TaskFlow¶

Os exemplos giram em torno de um gerenciador de tarefas. Nos Capítulos 6 e 7, ele é uma pequena API em FastAPI, com os dados em memória, testada com pytest e verificada por um pipeline do GitHub Actions. Dela nasce o TaskFlow: a mesma ideia para uma equipe, com banco SQLite, login, projetos, membros e permissões. É só a API, sem interface web.

O repositório tem uma etiqueta (tag) para cada etapa:

Tag Etapa
v1-memoria API em memória (Capítulo 6)
v2-pipeline pipeline, imagem e verificações de segurança (Capítulo 7)
v3-sqlite persistência
v4-login usuários e sessões
v5-equipe projetos, membros, responsável e estados da tarefa 
git clone https://github.com/lambdageo-edu/taskflow.git
cd taskflow
git checkout v3-sqlite   # vê o projeto como estava nesta etapa

As etiquetas são retratos do passado e não recebem correções posteriores. Para usar ou modificar o projeto, parta da branch main.
